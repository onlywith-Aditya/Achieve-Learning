-----> Application
    - How this application work?
    - Limitation of this application?
    - What type of this appplicaiton? It is Data Intensive Applicaiton vs Compute Intensive Application.

--> Latency-> It is time taken to response.

----------------------------------------------------|

--> Data Intensive Applciation(DIA)-> Core focus on data.

    -> Problem-> 
        a. Database response time is more.
        b. Network calls take time.
        c. Server work slowly.
    
    -> In this we don't tell client to upgrade the CPU, but we make changes in our system.

    -> Example->
        a. Instagram Feed.
        b. WhatsApp Message.
        c. Banking Transaction.
        d. Analytics Dashboard.
        e. Log Processing System.

    -> Worries->
        a. How fast can we read the data?
        b. How safely are we going to store the data?
        c. How many users can access it simultaneously.
    
    -> Components this process are lie->
        a. Databases
        b. Cashing
        c. Replication
        d. Sharding
        e. Consistency

----------------------------------------------------|

--> Compute Intensive Applicaiton(CIA)-> In this ammount of data retrievement from database is low, but calculation is high.

    -> Challenges->
        a. CPU/ GPU Bound.
    
    -> Example->
        a. Image Processing.
        b. Video Rendreing.
        c. ML Model Training.
        d. Simulation.

    -> Worries->
        a. How fast can we compute?
        b. Can we parallelize this work?
        c. How to reduce the computational cost?
        d. Can we use GPU instead of CPU?

----------------------------------------------------|

--> It can be both Data Intensive and Compute Intensive.
    -> Example->
        - Youtube-> 
            a. Data Intensive->  Serving Video
            b. Compute Intensive->  Recommendation Video
    
-----> How to know which feature to follow?
    -> If time lost in in data movement, then Data Intensive.
    -> If time lost in in computation movement, then Compute Intensive.

--> Domain Name System(DNS)-> 
    - There are two types of domains-> Main domain and sub domain.
    - System communicate with IP addresses.


    ---> Domain Resolver-> Do all this things.

        - This domain and IP we stored in server, and may be in multiple servers.

        - There are 13 root server in this world.(a to m)

        - This root server search for top level domain.-> .com, .in and etc.

        - Then root server send IP address of that service and server which are handling .com or top level domain.

        - They give IP address of Authoritative Name Server(GoDaddy).

        - Then we have to make call to them and then we get our domain and view our web page.

    ---> Cache

        - Domain Resolve is time taken process, but next time it will store information in Cache for fast access.    

        - Cache are stored in this three location->
            1. Browser Cache
            2. OS Cache
            3. DNS Resolver Cache

    ---> Zone
        
        - This different domain of one page, are create zone.
            - Ex-> India.com, India.in and etc.
