- System design is designgin a system in a manner that it can be scalable according to usablitiy.

- It is of two types->
    1. High level design(Designing)
        -> In which we design things like database, message queue and cache.
    
    2. Low lelve design(Coding)
        -> Design API 
        -> Class Diagram

----------------------------------------------------|

- Functional Requirement
    1. Functional Requirement
        -> User can signup and login.
        -> User can buy a subscription.
        -> User can play/pause a video..
    
    2. Non-Functional Requirement
        -> Secure system with authentication.
        -> Low latency for video.
        -> Scalable system

1. High Level Design-> GUIDE

    [a] Fundamentals
        - Serverless vs Serverful
        - Horizontal and Vertical Scaling
        - What are threads?
        - What are pages?
        - How deos the internet work?

    [b] database    
        - SQL vs NOSQL Database
        - In-memory Database
        - Data Replication and Migrartion
        - Data Partitioning
        - Sharding
    
    [c] Consitency and Avaiability
        - Data Consitency and its level
        - Isolation and its level
        - CAP Theoram
    
    [d] Cache 
        - What is Cache? (Redis, Memcahed)
        - Write Policies: write back, through and around
        - Replacement Policies: LFU, LRU, Segemnted LRU etc.
        - Content Delivery Networks(CDNs)

    [e] Networking
        - TCP vs UDP
        - What is http(1/2/3) vs https?
        - Web sockets
        - WebRTC & Video Streaming
    
    [f] Load Balancers
        - Load Balancing Algorithms(Stateless and Stateful)
        - Consitent Hashing
        - Proxy and Reverse Proxy
        - Rate Limiting    
    
    [g] Message Queues
        - Asynchronous Processing(Kafka, RabbitMQ)
        - Publisher-Subscriber Model

    [h] Monoliths vs Microserves
        - Why Microserves
        - Concept of 'Single Point of Failure'
        - Avoiding Cascading Failure
        - Containerization(Docker) 
    
    [i] Monitoring & Logging
        - Logging event and Monitorig metrics
        - Anomaly Detection
    
    [j] Security
        - Token for authentication
        - SSO & OAuth
        - Acess Control Lists and Rule Engines
        - Encryption
    
    [k] System Design Tradeoffs
        -  Push and Pull Architecture
        - Consistency and Avaiability
        - SQL vs NoSQL Database
        - Memory vs latency
        - Throughtput vs latency
        - Accuracy vs latency
